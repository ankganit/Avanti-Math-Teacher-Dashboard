# Add a PDF to the JEE Maths question bank

Avanti Fellows keeps the question bank inside the **teacher artifact**: https://claude.ai/artifact/UgXUYU8es1bDbPrckV3Cn8 ("Math Teacher Dashboard"). The student dashboard (https://claude.ai/artifact/JrF7haaQnwBT8Jh5QPCMcF) is separate: touch it only on explicit request. If the user deletes a test, ask whether to sync the student dashboard, because it keeps its own copy.

## STANDING RULE: ONE DATA SOURCE FOR EVERY SECTION (user rule, version 413)
Whatever is in the Question Bank must be shown in every section (Question Bank, DPPs, PYQs, Tests, exports). Since version 413 this is automatic: `teacher.js` builds the compact question list of the DPP library, PYQ papers, chapterwise PYQs and the test maker in the browser (`loadBank`, `qbCompact`) from the SAME files the Question Bank reads: `qb/data/pyq.json` and `qb/data/nonpyq.json` (shared download through `window.__qbPre`). So a question is added, changed, tagged or deleted in those two files ONLY. Never write question records into `bank.json`: the old `bank.json` is still published only for browsers that cached the previous page code (remove it in a later publish; do not update it). `bank-meta.json` holds only `chapters` and `syl`.

## STANDING RULE: NEVER SOLVE QUESTIONS (user rule, applies to every upload)
Claude never solves, re-works or sanity-checks a question's answer itself, with or without code or solver agents, unless the user explicitly asks in that message. Use the printed key exactly as given. If something looks wrong, FLAG it in `attention` and keep the printed key in `answer`. Flag only what is visible without solving: missing, empty or duplicated options, an answer letter that doesn't exist, a key marked unclear in the source (e.g. "Scan QR", "bonus"), damaged text, a question count that doesn't match the file, or extra text glued to an option. Never write a worked-out answer into a record or the reply (an `attention` text must never say "worked out here" or give a computed value). Tag level and topic by reading only. Papers printed "Morning Slot" are Shift 1 (label `<d> Mon yyyy Shift 1`, id `JM{yyyymmdd}1P{n}`).
Consequences used everywhere below: no solver agents, no key verification, no "worked out here" text, no solving of unkeyed questions. A key that is missing or invalid for the type (no key, "[NO KEY]", a letter on a numerical question) is not solved: hold the question back and list it to the user, or, when the user asks to add it anyway, add it with an empty `answer` (the UI shows "—") and `attention` "No answer key in the source file. Answer to be supplied by the teacher."; when the user later supplies the answer, set it and flag "answer supplied by the teacher, not verified" (or remove the flag if the user says so).

## STANDING RULE: NEVER DELETE OR SKIP (user rule, latest; overrides every older delete/skip rule in this skill)
- Nothing is deleted from the bank and no question of an uploaded file is skipped. Every question of every upload becomes a record, whatever it duplicates. No existing record is deleted, replaced or merged away.
- If a deletion or a skip ever seems necessary (a wrong or conflicting record, an archive copy that a new upload replaces, a paper with more questions than its maximum, a PYQ already in the bank), do NOT do it: list the cases with ids and ask the user first. Never leave a practice question out meanwhile; for a PYQ that already exists in the bank, hold the new copy back, list the pairs and ask.
- EXCEPTION: when the user explicitly orders a deletion (a named record, or "delete the repeated questions" for a source), do exactly that and nothing more; keep a JSON copy of the deleted records and give it to the user. Done: three Black Book records in version 397 and 411, and the 54 repeated Black Book questions in version 411 (see the skill `black-book-ques`).
- All questions that earlier uploads skipped as duplicates were restored for the Black Book (115 questions, version 390). Older deletions made in earlier sessions (practice questions removed because they duplicated a PYQ, AIEEE/IIT records removed to reach a paper's exact count, archive records replaced by full papers) are not recoverable from working files; if the user asks to restore them, search the artifact's version history or the original files.
- A practice question (any source) that is also a PYQ is kept and gets the PYQ tag (next section).

## PYQ TAG for practice questions (user rule, latest)
A practice question whose text matches a PYQ in pyq.json (same question, ratio about 0.9+ on normalised text, read the pair, compare answer VALUES) stays in nonpyq.json with its own id and source tag and also carries `pyq: true`, `pyq_ref` (PYQ id; several separated by ", "), `pyq_exam`, `pyq_year`, `pyq_paper` (copied from the PYQ record). The PYQ record stays untouched. Different numbers or letters = a variant, no tag. If the key differs from the PYQ's key, keep the printed key, tag it and flag both records in `attention`. Dashboard (version 390): the card shows a "PYQ" tag; Source "PYQs" alone shows only pyq.json; a practice source alone shows all its questions; "PYQs" + a source with PYQ-tagged records (Black Book) shows only that source's PYQ-tagged questions, with Exam/Year filters using the PYQ's own exam and year. After every PYQ upload re-check practice records (Black Book first) against the new PYQs and tag matches. Use rapidfuzz `fuzz.ratio` (difflib is too slow).

## MATH FORMATTING OF EVERY QUESTION (user rule: ALL uploads, ALL publishers, PYQs included)
Apply to every string of every new or changed record (question, options, answer, note, attention), only inside `\( \)` / `\[ \]`, then run the KaTeX check:
- Limits: write `\lim\limits_{x\to 0}` (never `{\lim}_{x\to 0}`, `\lim_{...}` or `\mathop{\lim}_`), so the variable sits BELOW `lim`, not at the side.
- Brackets: a round or square bracket pair whose content is tall (contains `\frac`, `\dfrac`, `\sum`, `\int`, `\prod`, `\lim`, `\binom`, `\begin`, `\sqrt`, `\vec`, ...) or that carries a tall exponent/subscript (for example `{(1+ax)}^{\frac{1}{x}}`) becomes `\left( ... \right)` / `\left[ ... \right]`, for example `f\left(\frac{1}{n}\right)`. Pairs that do not match (intervals like `(a, b]`) and short content are left alone.
- Use a script: balanced-bracket scan inside each math segment; after a `\left`, `\right`, `\big`... command skip the delimiter that follows it (otherwise `\left\left(` is produced); afterwards collapse any `\left\left` / `\right\right`; the script must be idempotent (running it twice changes nothing).
- Prefix for a combinatorial symbol: write `{}^{n-1}C_4` (never a bare `^{n-1}C_4` after an operator), because KaTeX rejects the bare form.
- Done once for the whole bank (version 373): about 579 practice records and 1,307 PYQ records changed. New uploads from any source must follow the same rule.

## FIGURES AND IMAGES (user rules, versions 398-410)
- Pictures in a question are black and white ONLY and must carry no watermark (ExamGOAL.COM and similar). Before adding or keeping an image: flatten it on white, take the minimum of the R, G, B channels, map 110 -> black and 195 -> white (this removes pale watermark text and turns blue or red lines black; light colour fills disappear), then save as a palette PNG. Scan every new image for colour (saturated pixels) and for pale repeating text and fix it before publishing. Done for 14 existing images in version 409.
- Compress every image (the page must stay fast): resize to at most 2.5 x the width it is shown at (shown width is the `<image width>` in the svg, usually 300 for PYQ crops; Black Book crops are shown at their own size), 16-32 colours, `optimize=True`. Choose the resolution per question: small diagrams need less, dense graphs with small labels need the full size. Version 406 cut the image bytes by about 35 percent.
- Record field `figure` = `{svg, w, h}`; the svg is `<svg ...><image href="data:image/png;base64,..." width=.. height=../></svg>`. The question text must contain the marker `{{figure}}` where the picture goes; without the marker the picture is invisible. Remove the marker and write "Figure not included in the source text" in `note` only when no picture is supplied. When a picture is added clear that note.
- A composite picture (graphs inside one image) is the default and is what exports, DPP pages and print show. For the Question Bank CARD view a question can also carry `figure.card`: `{text, imgs:[{svg,w,h}...], opts:[{svg,w,h}...]}`. `text` replaces the question text on the card and may use markers `{{f1}}`..`{{f9}}` at the END of a line (the line is shown as a row: its text, then that image); `opts` are one picture per option A-D, shown inside the options (2 per row). Examples: `BB-1-4-003` (matching: f(x) graph, Column I functions with the P, Q, R, S graphs next to them) and `BB-1-1-025` (the f(x) graph as the question image, graphs A-D as option images). Use it when the user wants graphs in Column II or in the options. The page code passes `card` through (ROWS figure in `qb-all.js`).
- Matching questions (Column I / Column II lines) are shown side by side in the card view (grid built from the `Column I:` and `Column II:` lines) and as a table in DPP pages.

## Source tag (publisher) of every upload
Every practice question carries a source tag (`publisher` in nonpyq.json). The list is open: any new DPP/question PDF can bring a new tag.
- Use the tag name the user gives in the message.
- If the user does not give one, read it from the PDF itself (cover, header, footer, watermark or title, for example the publisher or institute name) and use that. Say in the reply which tag was used and where it came from.
- If neither the user nor the PDF gives a tag, ask once.
- Keep the exact spelling and capitalisation of existing tags (VMC, Cengage, PPTs, Avanti and the others already in the bank). Do not create near-duplicates.
- PYQs have no publisher tag: the filter shows them as "PYQs". PYQ PDFs and PYQ Word/Markdown files (for example ExamGOAL chapter-wise PYQ PDFs, or a Word file of JEE Main PYQs with an answer key) get NO source tag, so do not ask for one.
- A NEW tag must be added to `SRC_VALS` in `qb/qb-all.js` (Question Bank Source dropdown) and to the count boxes of the dashboard header (`buildYearTiles` uses `SRC_VALS`). The DPP tab's Level 1-2-3 booklet source buttons (`PUBS` in `teacher.js`) are built automatically from the tags found in the data, so nothing to add there. Test that the Source dropdown shows the new tag with the right count and that the booklet shows it too.

## Input formats
- PDF: page images at about 115 dpi (`pdftoppm -r 115`); the text layer is often garbled for maths.
- Word (.docx) with an answer key table: convert with `pandoc file.docx -t markdown --wrap=none` and read the text; the maths comes through as LaTeX inside `$...$`. Clean the spacing artifacts (for example `\ = \` becomes `=`, per-character `\text{...}`, a trailing `\ ` after `\right.`). Use the key as printed (standing rule). Images of a docx are in `word/media/` after unzipping it.
- Markdown (.md) PYQ files from the user's pipeline (for example `AIEEE_Mathematics_2002_to_2005`): header `**Qn. [AIEEE 2002 | 19 May 2002 | Paper Q1]**`, stem, options as `> **(A)** ...`, per-year key tables and a master key; `[NO KEY]` marks a question without a key. They give the OFFICIAL paper question number ("Paper Qn"): use it as `qno` and in the id. Convert `$...$` to `\( \)`; turn a markdown table inside a stem into plain lines ("X: 1, 2, 3").
- Pandoc can silently DROP the answer-key table when the table has no `w:tblGrid` (the markdown then ends right after the "Answer Key" heading). Then read the key straight from `word/document.xml` (cell texts of the table in order: `Q12`, `B`, `Q13`, `7`, ...; `Q31*` with an asterisk = out of syllabus) and check that the number of answers equals the number of questions. Some keys are written like "A (Key: C)" or "D (actual value is ...)": keep the first letter and flag the source note in `attention`.
- Word files made by the user's own pipeline come in two families. (1) Clean: header `**Qn. \[12M22 | JEE Main 2026 (Online) 8th April Evening Shift\]**`, options one per line `> **(A)** ...`, key table at the end, ` | Out of Syllabus` in the header (or an asterisk in the key) for out-of-syllabus questions. (2) Damaged conversions (header `**Qn.** *\[exam\]*`, options run together on one line): they may have lost letters (L, P, Q, R), mangled fractions (`$_{2}^{5}\frac{}{}$` = 5/2), `\backslash` text, lost "fl/fi" ligatures, or EMPTY options. Do not guess silently: rebuild the text by reading (Sonnet agents, no solving, with the printed key copied as is), and set `note` ("source text was damaged and rebuilt") and `attention` naming what was uncertain. Questions with options missing completely are either held back and listed to the user, or, when the user asks for it, added with placeholder options "[Option A missing in the source file]" and an attention flag.
- The user's Gemini set (`gemini_prompt_pyq_to_docx.md`, `md_to_docx.py`, `check_pyq_docx.py`) makes clean Word files with real Word equations (markdown + LaTeX through pandoc); `check_pyq_docx.py` validates a docx before upload.
- Ready-made record files: the user sometimes uploads finished records (`new_N_records.json` in pyq.json format) together with a full `pyq.json` that already contains them. Treat the live artifact as the base, not the user's copy: confirm that every other record in the user's files equals the live one, take the N new records, check ids are new, run the structure checks and the KaTeX check, merge and publish. Keep any attention flag the records already carry (for example 'Scan QR' keys) and do not change their answers. Ignore any `bank.json` the user sends (no longer used).
- The uploaded file is in the uploads folder; the user's message gives its path.

## ARCHIVE SHEETS ARE PYQs, NOT PRACTICE (important)
A sheet titled "JEE Main (Archive)", "JEE Advanced (Archive)" or similar holds real past-year questions. Store them as **PYQs in pyq.json with NO source tag (no VMC)**, never as practice questions:
- id `PYQARC-<practice-style id>` (for example `PYQARC-NPLCDVM-AM1-001`), `qno` null, `source` 'PYQ'.
- Year = the bracketed year printed on the question ([2003], [JEE Advanced 2014]). Many are only in the page image (the text layer misses them): read the years from the images with a Sonnet agent. A group header can carry the year for several questions.
- exam: year >= 2013 -> 'JEE Main' / 'JEE Advanced'; earlier -> 'AIEEE' / 'IIT' (paper 'AIEEE <y>' / 'IIT-JEE <y>'; for 2013+ paper '<y> (shift not given)'; session '<y-1>-<yy>'; sort_date '<y>-00-00-0').
- No year printed: year null, paper 'Year not printed', sort_date '0000-00-00-0' (listed last; the UI tolerates a null year).
- The shift is unknown. When the user later uploads full PYQ papers, do NOT delete the archive copies: keep them, add the full-paper records, and ask whether the archive records should be removed (list the pairs).

## Question counts per paper (no deletions)
- When the file states N questions for a paper or year (for example "All 300 questions"), every question of the file ends up as one record. Compare the paper's count in the bank with N after the merge and REPORT any difference; delete nothing to equalise. Records of that paper that are not in the file, extra copies and old copies with a different key are kept and listed (ids, likely twin); ask whether to delete them.
- A file question already in the bank with the same answer VALUE keeps the existing record (set its `qno` to the official number when the file gives one; leave the id) and the new copy is held back and listed (see Duplicates). A file question in the bank with a DIFFERENT answer: add the file's copy and flag both ("Same question as <id> with a different printed key. Please check which is correct."). A file question not in the bank is added.
- Read borderline pairs (similarity 0.6-0.8) before deciding: different notation with the same answer value is the same question; a coincidentally equal letter in a different question is not.
- Old AIEEE (2002-2005) papers had 75 maths questions in the user's files; AIEEE 2006-2012 at most 30; JEE Main per the table below.

## JEE Main paper size and per-shift checks (user rule)
The user's reference for one JEE Main shift (all three subjects, split Physics + Chemistry + Maths):
- 2013 - 2019: 90 questions, 30 + 30 + 30. All compulsory MCQs, no numerical value questions.
- 2020: 75 questions, 25 + 25 + 25. Numerical value questions introduced: each subject 20 MCQs + 5 NVQs, all compulsory.
- 2021 - 2024: 90 questions (75 to attempt), 30 + 30 + 30. Choice introduced: each subject 20 MCQs (compulsory) + 10 NVQs (attempt any 5 of 10).
- 2025 - 2026: 75 questions, 25 + 25 + 25. Choice removed: fixed 20 MCQs + 5 NVQs per subject, all compulsory.
So ONE MATHS paper (one shift) has at most 30 questions in 2013-2019 (also the offline papers 2013-2018), 25 in 2020, 30 printed in 2021-2024 (25 to attempt), and 25 in 2025-2026. The user's words: a paper of 25 maths questions must not have a single extra question.
After every PYQ upload (and when asked to audit):
- Count the questions per shift over ALL chapters in pyq.json (group by `paper`). A shift with MORE than its maximum has extra questions: put an `attention` flag on each extra question: "Extra question: this shift has N questions in the bank but a JEE Main paper has only 25 (30)." and, if it has a lookalike, name it ("It looks like a duplicate of <id>"). The extras are the records with the highest `qno` (the continued numbers added last), or the records that are not in the uploaded file. Do NOT delete them (only flag; ask the user). A shift with fewer questions than the maximum is normal (chapters not uploaded yet). Do not apply the 25 cap to 2021-2024 or older papers.
- Similar questions in the same shift: compare the questions of the same `paper` (all chapters) after normalising the text; pairs with text similarity >= 0.85 get an `attention` flag on BOTH records: "Similar question in the same shift: <other id> (xx% same text). Answers: this X vs that Y. Probably the same question typed twice; please check which is correct." so the user sees that the two differ only by typing. Pairs between 0.70 and 0.85 are only mentioned in the reply. Append to an existing attention text with " | " and never duplicate a flag.
- Prevent the problem while uploading: compare every new question with ALL questions of its paper in any chapter before adding it; a near-match with the same answer value is held back and listed to the user (not added twice, not deleted), with a different answer value it is added and both records are flagged. Different notations (`\vec` vs `\overset{\rightarrow}`, flattened fractions like `152` for 15/2, `<!---->`, `=html`, `\lbrack`) fool a strict comparison: normalise them and compare answer VALUES loosely (letters and digits only).
- Report in the reply how many shifts are over their maximum and which questions were flagged.

## PYQ ids, papers, sessions and question numbers (learned from the uploads)
- **Id format for JEE Main PYQs from 2020 on:** `JM{yyyymmdd}{shift}{qn:02d}` with NO letter P. Examples already in the bank: `JM20250122109` (22 Jan 2025, shift 1, Q09), `JM20260408221` (8 Apr 2026, shift 2, Q21). Older 2023 records use `JM{yyyymmdd}{shift}P{qn:02d}` (for example `JM202304101P19`); do not copy the P form for new records. Pre-2020 shift papers use `JM{yyyymmdd}{shift}P{n}` (for example `JM201304091P5` = 9 Apr 2013 Shift 1 Q5; a printed "Morning Slot" is Shift 1); JEE Main offline (2013-2018) `JM{yyyymmdd}0P{n}`; AIEEE `AIEEE{yyyy}{MMdd}0P{n}`. When an id already exists (old records carry inflated numbers such as `...0P87`), use the chapter-style form `...0M{n}Q{qn}` or `...0M{n}` instead of overwriting.
- Ids MUST be unique across pyq.json and nonpyq.json (the DPP and test lists are built from them and look questions up by id). In version 413 nine pairs of 2021 JEE Main questions that shared an id (different questions with the same date, shift and number) were separated: the earlier record of each pair got a `D` after the date, for example `JM20210725D101`. Check uniqueness before every publish.
- IIT-JEE ids: `IIT{y}0000{0|1}Q{qn:02d}` (1 = Screening, 0 = the rest).
- Never invent placeholder tokens in ids (no `PLOG`, no `ARC`, no `X`). Ids must be exactly the pattern above (the one exception is the `D` of the nine separated 2021 ids).
- **Shift mapping:** Morning = Shift 1, Evening = Shift 2 (the bank uses this; for example 8 Apr 2026 Evening is Shift 2).
- **Paper label:** `'<d> <Mon> <yyyy> Shift <n>'`, for example `10 Apr 2023 Shift 1`, `25 Feb 2021 Shift 2`; offline papers `'<d> <Mon> <yyyy> (Offline)'` (JEE Main 2013 7 Apr, 2014 6 Apr, 2015 4 Apr, 2016 3 Apr, 2017 2 Apr, 2018 8 Apr; AIEEE 2002 19 May, 2003 11 May, 2004 23 May, 2005 8 May, 2006 30 Apr, 2007 29 Apr, 2008 27 Apr, 2009 26 Apr, 2010 25 Apr, 2011 1 May, 2012 29 Apr). Use the same wording as existing records. If a file prints another date (the AIEEE 2002-2005 file says 18 May 2003), keep the bank's label and mention the difference in the reply.
- **Session:** `'<y-1>-<yy>'` for every JEE Main date, for example 10 Apr 2023 -> `2022-23`, 26 Feb 2021 -> `2020-21`, 20 Jul 2021 -> `2020-21`, 9 Jan 2020 -> `2019-20`, 23 Jan 2026 -> `2025-26`.
- **sort_date:** `yyyy-mm-dd-shift`.
- **Question numbers:** use the OFFICIAL number when the file gives it ("Paper Q12"). Many PYQ sheets (for example a Word file with only the question text and key) do NOT give the paper's own question numbers. Then the question number is unknown, and you must not guess. Use `qno` null (as done for AIEEE 2006-2008) or, when the user wants numbers, the next free number for that paper: take the highest `qno` already on records with the same paper label (also scan ids with the same date+shift prefix; ids may carry chapter letters before the number, so use the trailing digits; ignore inflated numbers above 100 left by an old bug), add 1, and continue in the order the sheet lists them. Tell the user in the reply that these numbers continue the paper's sequence or are missing, and ask for the real numbers if they have them.
- Numbers of papers not yet in the bank start at 01.

## Record formats
- **PYQ** (pyq.json): `id, exam ('JEE Main'|'JEE Advanced'|'AIEEE'|'IIT'|'KCET'), year, session ('2024-25'), paper ('22 Jan 2025 Shift 2'), qno, type, class, chapter_code, chapter, difficulty (L1|L2|L3), question, options, answer, source_url, attention, figure, topic_code ('JM-12M19.n'), topic, sort_date ('yyyy-mm-dd-shift'), source 'PYQ', note, topic_status`, plus `oos: True` for out of syllabus. Ids: see the PYQ id section above (`JM{yyyymmdd}{shift}{qn:02d}` for 2020 on), `JA...` / `IIT...` for Advanced and IIT-JEE, `PYQARC-...` for archive sheets. Before 2013 JEE Main was AIEEE and JEE Advanced was IIT-JEE. `class` is 11 for chapters 11M*, 12 for 12M*.
- **Practice** (nonpyq.json): `id ('NP<BOOKCODE>-<sheet>-<qno:03d>' style, new prefix if another session already used it; Black Book uses BB-c-e-NNN), source 'Non-PYQ', book, section, exam ('JEE Main'|'JEE Advanced' = level only), year null, session '', paper, qno, part '', type (MCQ|MSQ|Numerical|Matching|Comprehension|Subjective), class, chapter_code, chapter, topic_code, topic, difficulty (L1|L2|L3), question, options (no (A) prefix), answer ('A', 'A,C' or a value), source_url '', ref_year, note, attention, figure, sort_date ('Z-<order>-<order>-<qno>-'), topic_status 'mapped', original_level, publisher (the source tag above)`, plus the optional PYQ tag fields `pyq, pyq_ref, pyq_exam, pyq_year, pyq_paper`.
- Unmapped topic: `topic_code 'UNMAPPED-<cc>'`, `topic 'Unmapped'`, `topic_status 'mapped'`. The DPPs show these as "Mixed problems".
- Math is KaTeX (`\( \)` / `\[ \]`), real newlines (never a literal backslash-n outside math), `{{figure}}` marker ONLY when a figure is supplied (see FIGURES AND IMAGES). Apply the MATH FORMATTING rule above to every record. Figures are `{svg,w,h}` inline SVG (a crop of the page as an embedded PNG data URI inside `<image href=...>`, or a hand-drawn SVG); graph options become "Graph (A)" and so on. If a question needs a figure that is not supplied, remove the `{{figure}}` marker from the stem (a literal marker shows on the card) and put "Figure not included in the source text" in `note`. Maths inside `note`/`attention` must also be wrapped in `\( \)`. Fix converter artefacts: `\text{∑}` -> `\sum`, a double superscript like `\sum_{r=0}^{22}^{22}C_r` -> `\sum_{r=0}^{22}{}^{22}C_r`, a bare `<` followed by a letter -> `\lt`.
- A multi-letter key on an MCQ makes it MSQ ('A,C'). Prove/show questions are Subjective with the answer text "Proof question: ...". True/False questions are MCQ with options True/False (A = True, B = False).
- Existing records sometimes list MCQ options in a different order from the printed paper, so the letter in the record can differ from the printed letter while the value is the same. When comparing a new question with an existing one, compare the answer VALUE, not the letter.

## Levels (matter for the DPPs)
Every question (practice AND PYQ) gets exactly L1, L2 or L3, per the `practice-question-levels` skill, judged by reading only. Never use Easy/Medium/Hard, L0, L4. Keep the source label in `original_level` only.
The DPPs want at least 5 L1 + 5 L2 + 5 L3 each, and L1 (easy) questions are the scarce resource (most chapters have only 4-11 L1 questions). Judge levels honestly with the rubric, but when a sheet has no difficulty labels do not drift towards L2/L3: genuinely direct one-step questions are L1.
After every upload, report the L1/L2/L3 count of each chapter that received questions and warn when a chapter has fewer L1 questions than 5 x its number of DPPs. Count from the data (`chapter_code` and `difficulty`) after the merge.

## Subtopic DPPs (Practice Questions) in the DPP tab
Built automatically from the non-PYQ questions of each chapter (`buildSubDpps` in `teacher.js`); nothing to publish except the data. The user wants this flexible, not rigid:
- Number of DPPs per chapter = min(lectures from the table above, floor(questions / 13)), at least 1. A chapter with few questions gets fewer DPPs than lectures; a chapter with many gets exactly its lectures. A chapter with only PYQs and no practice questions has 0 DPPs.
- Each DPP is on its own topic(s): a topic with enough questions gets its own DPP, a big topic is spread over several DPPs with different questions in each, and small neighbouring topics are merged into one DPP. Never repeat the same heading and the same questions in several DPPs.
- Each DPP is ONE A4 side with 15 to 20 questions: at least 5 L1 + 5 L2 + 5 L3 (a gap in a level is filled from L2 first, then the other level), then up to 5 extra questions while they still fit with text between 10.5 and 11.5 pt. If the page is too crowded the extras are dropped first, then the tallest questions (never below 12 questions).

- The Level 1-2-3 booklet lists every source tag found in the data, all ticked by default.
- After an upload, report how the DPP count of each affected chapter changed against its lectures, and list the chapters that have fewer DPPs than lectures because they lack questions. PYQ-only uploads do not change practice DPPs.

Source = PYQs plus the source tags (a PYQ-tagged practice question joins the "PYQs" selection only when its own source is ticked too). Exam = JEE Main, JEE Advanced, AIEEE, IIT, KCET. Year, Source, Exam and Question type are multi-select dropdowns. The DPP "Download PYQs topic wise" page has Exam and Year multi-select dropdowns.

In that table the `JEE Main` column counts JEE Main + AIEEE and `JEE Adv` counts JEE Advanced + IIT-JEE (the user asked for this); Total is unchanged. ## Duplicates (nothing is deleted or skipped)
Check every new set against ALL existing PYQs and practice questions by text. Normalise (strip `\( \)`, `\left`, `\right`, `\tfrac`, `\dfrac`, `\frac`, braces, spaces, lower-case) and use rapidfuzz `fuzz.ratio`; 1.0 after normalising is certain, about 0.9+ needs reading. Read the pairs: questions sharing a passage, or with different numbers or answers, are NOT duplicates. Compare answer VALUES, not letters.
- New practice question that duplicates a PYQ (archive PYQs included): add it with the PYQ tag; the PYQ stays.
- New practice question that repeats a practice question: add it anyway; report overlaps with other publishers.
- New PYQ already in the bank as a PYQ with the same answer VALUE (same paper label, even at similarity 0.3-0.6; read pairs below 0.6): do not add a second copy and do not delete; hold it back, list the pairs (new id, existing id) and ask. The existing copy may sit in another chapter.
- New PYQ matching an archive record (`PYQARC-*`): add the new one, keep the archive record, ask whether the archive record should go.
- Same question twice inside one PDF: add both; note the repeat in `attention` of the later copy.
- Same question in two different years: keep both.
- Near-match with a different answer value: add the new one, keep the old, flag both ("Same question already in the bank (<id>) with a different answer ... Please check which is correct.").

## Mixed-chapter sheets
A sheet can mix chapters (for example Limits + Continuity & Differentiability). Give every question its own chapter_code and topic. Questions clearly from another chapter go to that chapter with the nearest topic or UNMAPPED (monotonicity -> 12M18.4, definite integrals -> 12M20, functions/logs -> 12M13, inverse trig sums -> 12M14); Rolle/Lagrange stay in 12M17.7. The same holds for PYQ PDFs: chapter by what the question is about (a vectors question inside a 3D PDF goes to 12M22; sequences to 11M6; complex numbers to 11M5; Leibniz-rule questions to 12M20; area under the curve to 12M20). Mixed matching questions stay in the PDF's chapter.

## Answers and flags
- Keep the printed key exactly as given (standing rule). If the key looks doubtful to the user, they will say so; do not check it yourself. Put quirks (printed symbol differs, figure missing) in `note`.
- Flag only what is visible without solving: missing, empty or duplicated options; an answer letter that does not exist among the options; a key marked unclear in the source ("Scan QR", "bonus", "[NO KEY]", "A (Key: C)"); damaged text; a question count that does not match the file; extra text glued to an option. Quote the source note in `attention` and keep the printed letter in `answer`.
- If the printed answer is missing, cut off or unreadable, do NOT solve it: hold the question back and list it to the user (or add it with an empty answer and the flag above when the user asks).
- A companion SOLUTIONS PDF may be used to READ a missing key (solution headings look like `256.(CD)`), never to derive one.
- Print typos in the source: correct the question text and say so in `attention`.
- Two options equal, key ambiguous, small print unreadable: always flag, never guess silently. If two options print identically, re-read the page image first: it is usually a lost minus sign in transcription. When the user explicitly asks for best-guess options on damaged text, add them with an attention flag "options need to be checked".
- True/False questions: some PDFs print the same letter (for example B) for every one. Keep the key and flag that every key is the same letter; do not work out the answers.
- Proof-type questions (prove/show a given statement, key says "Solve it") in PYQ PDFs are listed in the report; ask the user once whether to add them as unkeyed "Proof question" entries (do not drop them silently).
- "Full explanation" solutions are added only when the user sends them. The user wants SHORT, math-only explanations.
- When the user says a Review or Attention tag is wrong or fixed, remove the `note` / `attention` field of that record.

## ExamGOAL-style PYQ PDFs (chapter-wise, answer key at the end)
- Layout: cover page, then sections (MCQ single, MCQ more than one, Numerical, Subjective, Fill in the Blanks, True or False; their order differs per PDF). Each question is `Qn.` plus a header line (`JEE Advanced 2025 Paper 1 Online`, `IIT-JEE 2007`, `IIT-JEE 2005 Screening`, `IIT-JEE 2000 Mains`). The text layer has no maths: transcribe from page images (`pdftoppm -r 115`). The page images carry a pale "ExamGOAL.COM" watermark: remove it from every cropped figure (FIGURES AND IMAGES).
- Build `hdr.json` (question number to header) and the section of every question from the text. MCQ/MSQ letters and numerical values are in the text key (parse per question number); maths answers (Subjective, Fill, True/False) are only in the key page images, so the transcription agents also read those key pages and return `printed_answer` (copying it, not deriving it).
- Split into chunks of about 5 pages or 26 questions: one brief file for the PDF plus one assignment file per chunk, and send each agent a one-line prompt pointing at the files. At most 20 subagents run at once: launch 20 or fewer and re-launch any that hit the limit.
- Ids and dates: JEE Advanced 2025/2026 use sort_date `y-05-30-paper` and id `JA{y}0530{paper}...`; earlier JEE Advanced `JA{y}0000{paper}...`; IIT-JEE records use exam `IIT`, paper `IIT-JEE {y}` plus ` Paper N`, ` Screening` or ` Mains` when printed, id `IIT{y}0000{paper}...`. Add a chapter suffix and the question number so ids are unique across PDFs.
- Key handling: copy the printed key; no solver agents. Structural problems only (see Answers and flags).

## Cost rule (very important)
Credits are limited. Do the heavy work in cheaper subagents:
- PDF page reading + LaTeX transcription: Agent with `model: "sonnet"`, using a brief file; page images at about 115 dpi (the text layer is often garbled); prefer `pdftotext` only when maths is real text.
- Topic and level tagging of typed questions: `model: "haiku"`; for big uploads use Sonnet tagging agents in batches of about 58-80 questions, each writing `out{k}.json` as `{"<id>": [chapter_code, topic_code, level]}` (classification by reading only, never solving). Always give the agents the full prompt text (input path, chapters.json and topics.json paths, level rubric, output path): an empty or placeholder prompt makes them guess the task.
- Keep the main conversation small: split pages, merge, validate, publish. Never read all pages yourself.
- If the PDF ends with an answer key, read the key pages as images once and fill answers in code.
- A Word or Markdown file with the text already present needs no page images; read it with pandoc and work in the main conversation if it is under about 20 questions. A cleaned Markdown file with hundreds of questions is parsed with a Python script; only the topic/level tagging goes to agents.
- An uploaded PDF is cheaper and more reliable than a link. Some sites block automated fetching: never work around a blocked fetch with curl or other tools; ask the user to download and attach the PDF.
- If a daily limit hits 100%, stop and continue after the reset (use `send_later` / scheduled-task tools, never the local Cron tools).

## Escalate to Opus when Sonnet can't do it right
Accuracy matters more than cost. Re-run only the failing range with an Agent using `model: "opus"` when:
- LaTeX fails validation and a single quick fix doesn't solve it.
- Question count doesn't match the PDF numbering (missing, merged or duplicated questions).
- Options are missing or mixed into the question text.
- Answer-key letters/values don't line up with question numbers or types.
- Dense notation (matrices, determinants, integrals with limits, piecewise), figures, tables, Matching or Comprehension sets.
- Scanned pages, guesses, "unclear" or placeholder text, or the subagent fails or returns malformed JSON twice.

## No-mistakes checks (run before publishing)
- Each question number present exactly once; count matches the PDF or Word file (every question of the file is a record).
- MCQ has the printed number of options; MSQ letters exist in the options; Numerical answers are numbers; every answer filled (except the held-back or empty-answer cases flagged above).
- Every KaTeX snippet renders: check with `node` and `katex.renderToString(..., {throwOnError:true})` from a local KaTeX package (`npm install katex@0.16.9` in a scratch folder), zero failures; also check for undelimited math (a `\command` outside `\( \)`) and literal `\n`. Also confirm the MATH FORMATTING rule: no `{\lim}_` or `\lim_` left, no `\left\left`.
- chapter_code in 11M1-12M24 or 12M27 and topic_code exists in topics (or is `UNMAPPED-<cc>`).
- Every practice question has its source tag, and the tag exists in the filter lists.
- No duplicate ids across pyq.json and nonpyq.json; PYQ-tagged records have `pyq_ref` ids that exist in pyq.json; every exam name is one the DPP library knows (JEE Main, JEE Advanced, AIEEE, IIT) unless the user decided otherwise (KCET is Question Bank only for now).
- Every new image: black and white, no watermark, compressed (FIGURES AND IMAGES), and the `{{figure}}` marker present.
- No placeholder tokens in ids (for example `PLOG`).
- Per-shift/paper count and similar-question checks (extras flagged, never removed; similar pairs flagged on both records).
- Spot-check 3 random questions per sheet or PDF against the page image (one Sonnet agent can do about 21); if any mismatch, escalate that range to Opus.
- Render a few new cards in the browser (playwright, chromium at /opt/pw-browsers/chromium, `python3 -m http.server` from the site folder, KaTeX routed from a local copy): option layout for long integral options, a figure card, an archive PYQ without a year, and no literal `{{figure}}` showing; also a limit card (variable below `lim`) and a card with large brackets; after a PYQ-tag change, the Source filter combinations (PYQs only, a source only, PYQs + that source). Also open the DPPs and PYQs tabs once and check the counts (they read the same data).
- Anything still uncertain goes in `note` or `attention`. Never upload partial or unvalidated data.

## Steps
1. Map pages to sheets/sections with a header scan per page (or read the Word/Markdown text); locate the answer-key pages; find the source tag (user's message, else the PDF; PYQ files need none).
2. Spawn Sonnet agents per page range (aligned to sheet boundaries), each writing JSON to the scratchpad. Skip agents for short Word files and for cleaned Markdown files that a script can parse.
3. Merge in Python; fill answers from the printed key; assign chapter (12M.. or 11M..), topic, L1/L2/L3 and the source tag; archive sheets become PYQs. Build PYQ ids and question numbers with the rules in the PYQ id section. Apply the MATH FORMATTING rule to all text. Clean and compress every image.
4. Validate (checks above). Do not solve or verify keys; flag only structural problems.
5. Check duplicates against all PYQs, archive records and practice questions (rapidfuzz), read the pairs, tag practice questions that are PYQs, flag different keys; NOTHING is deleted or skipped. Append to pyq.json / nonpyq.json ONLY (read the live files first and `cmp` with the local base; the DPP and test lists follow automatically); register a new tag in `SRC_VALS` if needed; run the per-shift count and similar-question checks; publish with the `files` map.
6. Reply in a few lines: how many added (practice vs PYQ), the source tag used (and where it came from), per sheet or PDF, how many carry the PYQ tag (ids), overlaps with other sources, how many flagged (list the `attention` ones, especially keys marked unclear in the source), that the printed key was used as given, whether question numbers are official, continued or missing, the L1/L2/L3 balance per chapter, DPPs per chapter against lectures, papers over their question maximum, held-back questions, and any decision needed (every case where a deletion would be needed: ask, never delete).
