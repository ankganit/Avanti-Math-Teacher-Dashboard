# Black Book questions in the JEE Maths question bank

Book: "Advanced Problems in Mathematics for JEE (Advanced)", 12th edition 2026 (source tag "Black Book"). The user uploads it chapter by chapter as cleaned Markdown (or Word) files. These are the user's own rules for this book.

This skill covers only what is special to the Black Book. Everything shared with other uploads (teacher artifact URL, publishing steps and the live-file read/`cmp`/`files`-map procedure, record formats of the data files, KaTeX check, MATH FORMATTING rule for limits and brackets, never-solve rule, NEVER-DELETE rule, figures and images rules, level rubric via the `practice-question-levels` skill, DPP counts, cost rule with Sonnet agents) is in the skill `jee-question-bank-add-pdf`: read it and follow it together with this one. Where the two differ, this skill wins for Black Book files.

The teacher artifact is https://claude.ai/artifact/UgXUYU8es1bDbPrckV3Cn8. The student dashboard is separate; do not touch it unless asked.

## ONE DATA SOURCE (user rule, version 413)
Whatever is in the Question Bank must show in every section (DPPs, PYQs, Tests, exports). Since version 413 the DPP/PYQ/test list is built in the browser from `qb/data/pyq.json` and `qb/data/nonpyq.json` (the same files as the Question Bank). So a Black Book change is made in `qb/data/nonpyq.json` ONLY. Do NOT write question records into `bank.json` any more (the old file is still published for browsers that cached the old page code and is not updated; it will be removed). `bank-meta.json` holds only `chapters` and `syl`.

## NEVER DELETE OR SKIP A BLACK BOOK QUESTION (user rule, latest; replaces the old duplicate-skipping rule)
- Every question of the uploaded file is added to the bank, whatever it duplicates. Nothing is skipped, nothing is deleted from the bank, and no existing record is removed or replaced.
- If a deletion ever seems necessary (a wrong record, a conflicting copy), do NOT delete: list the case and ask the user first.
- EXCEPTION: when the user names a record and says to delete it, delete exactly that record (from nonpyq.json). Done so far: `BB-13-5-003` (version 397; the question is not present in the original source), `BB-16-1-035` (version 397; same question as `BB-16-1-034`; the user said to delete the second copy) and the 54 repeated questions of version 411 (see REPEATED BLACK BOOK QUESTIONS below; `BB-16-1-077` was one of them). Never extend such a deletion to other records.
- All 115 questions that were skipped as duplicates in the earlier uploads (book chapters 1-26) were restored in version 390; nothing is outstanding.

## REPEATED BLACK BOOK QUESTIONS (user rule, version 411)
The book prints some questions twice. On UPLOAD both copies are added (never skipped) and the later copy gets the `attention` note "Same question as BB-x in this book (printed twice).". When the user says to remove the repeats: keep the FIRST copy in book order (book chapter, then exercise, then question number) and delete the other copies from nonpyq.json, then remove the "printed twice" tag (`attention`) from the kept record. Which records count as repeats: the ones tagged "printed twice" AND exact copies without a tag (same question text, same options, same answer, same part letter). Two copies with DIFFERENT answers are not touched: list them and ask. If a deleted copy carries a PYQ tag that the kept copy lacks, move the tag fields to the kept record. Check that no saved test (`tests-data` in index.html) or flag uses a deleted id, and save the deleted records to a JSON file for the user. Version 411 deleted 54 records (43 tagged + 11 exact copies); the file was `removed_black_book_duplicates.json`.

## PASSAGE PARTS GET A, B, C (user rule, latest, version 396)
A question of the book with several parts that share one passage (Exercise 3 Comprehension, also the two Exercise-2 comprehension groups) is ONE question in the book and has ONE number. It must not use one number per part.
- The id is the number of the group's FIRST part plus a letter at the end: `BB-10-3-001A`, `BB-10-3-001B`, `BB-10-3-001C` (book chapter 10, Exercise 3, question 1, parts A to C). Letters follow the order of the parts: A, B, C, D.
- NEVER renumber the other questions: every question that is not a part of a group keeps its number, so the ids of everything else stay as they are (renumbering would affect all questions, tests and flags). The numbers of the later parts (002, 003 in the example) simply do not exist as ids any more.
- Record fields: `id` = the lettered code; `qno` = the shared number (001 -> 1) for every part; `part` = 'A', 'B', 'C'; `sort_date` unchanged (it keeps the parts in order). The passage text is still prepended to each part's question text.
- How to find the parts: consecutive records of the same exercise whose question text begins with the same passage (common prefix of about 50 characters or more, or a shared first sentence/line); read the pairs. Short passages can share fewer characters: also scan consecutive records with a common prefix of about 25 characters and read them. Version 396 changed 106 groups (63 with two parts, 43 with three; 255 records, all Comprehension records). Matching questions (Column I / Column II) share only the line "Match the following ..." and are separate questions, NOT parts; Exercise-1 questions that merely start alike are separate questions.
- For a NEW upload: build the groups while parsing (a `### Paragraph for Question Nos. a to b` heading or `> Paragraph for ...` line marks one group; the numbers a..b are the parts), give the group the number of its first part and letter the parts. The next question after the group keeps its own file number.
- Looking up a code: `BB-10-3-001` (no letter) means the group; say that it has parts A, B, C and list them.
- Nothing else in the dashboard (tests, must.json, teacher.js, pyq_ref) used Black Book ids when this was done; saved teacher flags in the `flags` database under an old part id (for example `BB-10-3-002`) would not find the question any more; tell the user if the old id of a flagged question is mentioned.

## PYQ TAG (user rule, latest)
A Black Book question that is also a previous-year question (same question as a record in pyq.json: text similarity about 0.9 and above, or the same question with a different key) is kept as its own Black Book record (`BB-...` id, `publisher` 'Black Book') AND gets the PYQ tag. The PYQ record in pyq.json stays untouched. Variants with different numbers or letters (for example base 2 instead of base a, a different interval) are NOT PYQs: no tag.
- Fields added to the nonpyq.json record: `pyq: true`, `pyq_ref` (the PYQ id; several ids separated by ", "), `pyq_exam`, `pyq_year`, `pyq_paper` (copied from the first referenced PYQ record). Nothing else to update: the DPP/test list reads these fields from nonpyq.json.
- Dashboard behaviour (built in qb-all.js, version 390): the card shows a "PYQ" tag with the paper next to the Black Book tag. Source filter "Black Book" alone shows every Black Book question (PYQ-tagged ones included); "PYQs" alone shows only pyq.json (no duplicates); "PYQs" + "Black Book" together show ONLY the Black Book questions that are PYQs, and the Exam / Year filters then use the PYQ's own exam and year (for example AIEEE 2004). The same rule applies to any other source that has PYQ-tagged records.
- How to find them: compare every new record with all PYQs (normalised text, rapidfuzz `fuzz.ratio` is fast; difflib is too slow for thousands of pairs) and READ the pairs from ratio 0.9 up; use the answer VALUE (option text), not the letter. When the key differs from the PYQ's key, keep the printed key, add the PYQ tag AND flag both records in `attention` ("Same question as <exam> (<id>), whose key differs from this book's key. Please check which is correct."). A question printed twice in the book gets an `attention` note "Same question as BB-x in this book (printed twice)." on the later copy, and a PYQ tag if the first copy has one (removal of repeats only by the REPEATED BLACK BOOK QUESTIONS rule above).
- After every PYQ upload (any source) also re-check the Black Book records against the newly added PYQs and tag the matches. When the PYQs of a year are replaced (for example JEE Main 2026 was replaced in version 394), re-check the `pyq_ref` of Black Book records that pointed to that year: keep the tag when the text still matches (ratio >= 0.88), otherwise re-point or remove it.
- State after version 390: 84 Black Book questions carry the PYQ tag (46 AIEEE, 24 IIT, 11 JEE Main, 3 KCET). After version 411 (two tagged repeats deleted, the kept copies carry the same tags): 82.

## CHAPTER RULE (user rule)
- The USER tells, in the upload message, the bank chapter the file's questions go to (for example "22 and 23 to Trigonometry"). Put every question of that file in that chapter. Do NOT split the content, do NOT move any question to another chapter because of what it is about, and do not use the book chapter name or a table of your own to choose the chapter.
- If the user did not name the chapter, ASK before adding anything (one short question, naming the chapters you suspect from the file's heading; I propose a mapping and the user confirms). Never guess. If the user names a chapter that does not exist (for example 11M14), ask which existing chapter they mean.
- A new chapter the user names (for example 12M27) is created in chapters.json, topics.json and bank-meta.json (`chapters` and `syl`); ask whether to create the topics or leave everything Unmapped.
- Inside the chapter choose the best topic from topics.json (topic and level by reading only); if no topic of that chapter fits use `UNMAPPED-<chapter_code>` (topic 'Unmapped', shown as "Mixed problems").
- If the user says one file goes to two chapters (as book chapter 5 went to Indefinite and Definite Integration, and book chapter 26 to Vectors and 3D), split exactly as the user says: the tagging agents choose the chapter of each question by reading, from the two chapters named.

## Question codes: BB-<book chapter>-<exercise>-<NNN> (also the record id)
The code is the record id. Format `BB-<book chapter number>-<exercise 1-5>-<question no. in 3 digits>`; example `BB-2-1-021` = book chapter 2, Exercise 1, Q.No. 021. A part of a passage question has a letter at the end (`BB-10-3-001A`, see the PASSAGE PARTS rule). All Black Book records in the bank have this id (the old `NPBB2-E1-021` ids no longer exist). The user sends codes in this format; also accept sloppy spellings (`BB2-E1-021`, `bb 2 1 21`, old `NPBB2-E1-021`) and normalise them. Look the record up by id in nonpyq.json and say its chapter and topic. An old-style code without chapter: search all Black Book records for that exercise and number; if exactly one matches use it, if several match list them and ask. The book chapter number is read from the file heading, not from the bank chapter. Ids must be unique across pyq.json and nonpyq.json. Since version 390 there are no gaps: every printed question has a record (records later deleted on the user's order are listed above).

## Record format of a Black Book question (nonpyq.json only)
- `id` = the code, `source` 'Non-PYQ', `book` 'Black Book', `publisher` 'Black Book', `exam` 'JEE Advanced', `year` null, `class` per chapter, `qno` = the book's number (the shared number for the parts of a passage question), `part` = '' (or 'A', 'B', 'C' for the parts of a passage question), `original_level` 'Exercise-<e>', `topic_status` 'mapped'. PYQ-tagged records also carry the PYQ fields above. The compact list used by the DPPs and tests is built from these fields in the browser; nothing is written to bank.json.
- `section`: 'Exercise-1 (Single Correct)', 'Exercise-2 (One or More Correct)', 'Exercise-3 (Comprehension)', 'Exercise-4 (Matching)', 'Exercise-5 (Subjective)'. `paper`: 'Black Book · <Book chapter name> · Exercise-<e>'. `sort_date`: `Z-{e}-{c:03d}-{qno:04d}` (c = book chapter number); for passage parts keep the sort_date the records already have, so the parts stay in order. The dashboard's `exOf` reads the exercise from `paper`, then overrides by `type` (Matching -> 4, Numerical/Subjective -> 5).
- Types: Exercise 1 MCQ; Exercise 2 MSQ (also when the printed key is a single letter; answer 'A,C' style); Exercise 3 Comprehension (MCQ with a passage); Exercise 4 Matching; Exercise 5 Numerical (answer = the printed number). A non-numerical printed key in Exercise 5 makes the type Subjective, with the key as printed in `\( \)`.
- Comprehension: the passage text is prepended to the question text of EACH of its parts, then a newline, then the question; options A-D as usual. All parts of one passage form one question: they share one number and get the letters A, B, C (see the PASSAGE PARTS rule); question numbers of other questions run on as printed. The passage line can read `> Paragraph for Question Nos. 1 to 3Let ...` with the text glued to the numbers.
- Matching: question text = stem + `\nColumn I:\n(A) ...\nColumn II:\n(P) ...` (each entry on its own line); `options` []; answer in the form `A  →  R; B  →  S; C  →  P; D  →  Q` (two spaces around the arrow; several letters like `A  →  P, Q, S`; source arrows `->` are converted). Each matching question is a separate question with its own number. The Question Bank card shows Column I and Column II side by side (version 405, built in qb-all.js from the lines `Column I:` / `Column II:`), and the DPP pages show them as a table.
- Figures: the cleaned files carry `*[Diagram: ...]*`, `[Diagram: ...]`, `*[Graph (a): ...]*` and `Figure:` lines instead of pictures. Without a picture from the user, do not draw them: remove the lines from the question, set `figure` null, and put "Figure not included in the source text." plus the file's description in `note` (descriptions with maths wrapped in `\( \)`). Graph options become 'Graph (A)'..'Graph (D)'. When the user DOES supply the pictures (the Word file of the book: 13 questions in version 398; BB-1-4-003 and BB-1-1-025 from the user's images), build the figure from them with the FIGURES AND IMAGES rules of `jee-question-bank-add-pdf` (black and white, compressed, `{{figure}}` marker, and for matching questions with graphs in Column II or graph options the `figure.card` layout) and clear the "Figure not included" note.
- The dashboard's chapter-count table has a Black Book column (`src_BlackBook`), and "Black Book" is already registered in `SRC_VALS` and the `PUBS` order list; nothing to register.
- A `note` makes the card show a yellow "Review" tag; an `attention` makes it show a red "Attention" tag. When the user says a tag is wrong or fixed, remove that field from the record (for example `BB-10-3-001A-C` note and `BB-16-5-005` attention were removed in version 410).

## Source file format (user's cleaned Markdown / Word)
- Per book chapter a heading (`# Chapter N: ...` or `## CHAPTER 22: COMPOUND ANGLES`), then exercise headings (`## Exercise-1 ...` or `### Exercise-1 : Single Choice Problems`) with answer blocks (`### Answer Key`, `### Answers — Exercise-1`). Questions are `**Question N.** text` or `N. text`, followed by a pipe table `| (a) .. | (b) .. |` / `| (c) .. | (d) .. |` (header row `| Option | Option |` to ignore); comprehension has `### Paragraph for Question Nos. a to b` or `> Paragraph for ...`; matching has a `Column I | Column II` table under `#### Question N` (a stem can follow the number); Exercise 5 has no options.
- Converter artefacts: every digit of some numbers may be replaced by `https://www.google.com/search?q=<digit>`: delete the prefix everywhere before parsing. Limits are printed `{\lim}_{x\to 0}`: the MATH FORMATTING rule of the main skill turns them into `\lim\limits_{x\to 0}` and adds large brackets.
- Answer keys come in several layouts: `1. (b)` grids, `**Q1** | (b)` cells, a header row of numbers over a row of `(c)` or plain values (ex 5), a one-number row over `A -> S; B -> R ...` (ex 4), `1. 26` for numericals, and headings like `Answer Key — Exercise-1`. Parse the key per exercise (header-row keys can be `1.` or `1`), check that the key count equals the question count of the exercise, and use the printed key as is (never solve). Comprehension keys are listed per printed question number; map them to the parts A, B, C of the group in order.
- Convert `$...$` to `\( \)`; fix `\text{∑}` -> `\sum`, bare `<` followed by a letter inside maths -> `\lt `, `\text{log}x` -> `\log x` (never glue a name to the next letter: `\logx` fails in KaTeX), `\lbrack/\rbrack` -> `[ ]`, `\vert  b` spacing, `\text{∘}` -> `^{\circ}`, `(f^{-1}')(2)` style double primes -> `(f^{-1})'(2)`, plain-text maths inside options wrapped in `\( \)`. Then apply the MATH FORMATTING rule (collapse `\left\left`). Parse and build the records in a Python script (no agents needed for the text), then run the KaTeX check (zero failures, no undelimited `\command`).
- Tagging: topic and level only, by reading, with Sonnet agents in batches of about 58-80 questions. Give them the chapter the user named (FIXED, except the split chapters), the topic list of that chapter from topics.json, and the level rubric (full prompt text, input and output paths). They choose only topic and L1/L2/L3 (and the chapter for a split file). The parts of one passage get the same topic unless the parts clearly test different topics.
- Levels: the book is hard (JEE Advanced). Judge honestly with the rubric; do not force L1. Report the L1/L2/L3 counts per chapter after each upload and warn when a chapter has fewer L1 than 5 x its DPPs (12M14, 12M22 and 12M23 have only 3, 1 and 1 L1).
- Local test: copy the data and `qb-all.js` into a `tsite/` folder, serve it with `python3 -m http.server 8765` and drive it with playwright (Source dropdown: tick Black Book, then PYQs; expect exactly the PYQ-tagged count).

## Duplicates in Black Book uploads (everything is kept on upload)
- A question already in the bank as a PYQ: add it with the PYQ tag (see above). The PYQ stays.
- A question printed twice in the book (same text, same answer): add both; note the repeat in `attention` of the later copy. It is deleted only when the user says so, by the REPEATED BLACK BOOK QUESTIONS rule (keep the first, delete the later copies, remove the tag).
- Overlaps with other publishers' practice questions (VMC, Cengage): add and count in the reply.
- A variant with different numbers or letters: add, no PYQ tag.
- Compare answer VALUES, not letters. When keys differ for the same question (PYQ or repeat in the book), keep the printed keys and flag both records.
- Report the counts of PYQ-tagged, repeated and flagged questions in the reply; nothing is listed as "skipped".

## Re-uploading a repaired / clean file of a chapter already in the bank
The user sometimes sends a repaired file for a chapter already uploaded (Functions was). Then: keep the ids, chapter, topic, level and printed answer of every existing record; update only `question`, `options` and `note` from the clean file, with the MATH FORMATTING rule; add the questions the clean file has and the bank lacks (no skipping); report how many were updated and added, and any case where the printed key differs from the stored answer (do not change it silently; ask). Match passage parts by their lettered ids (`BB-10-3-001A`); a clean file that numbers each part separately maps its numbers onto the group in order.
